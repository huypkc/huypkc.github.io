How I work

Build first.
Verify deeply.
Release honestly.

Release engineering is part of building, not the part that comes after. I like products whose important claims can be checked — and I only claim what has actually been verified.

01 · SCOPE

Start with the constraint. What a product refuses to do is often the most important decision in it.

02 · BUILD

Keep boundaries narrow, so storage, cryptography, domain logic and UI never leak into one another.

03 · VERIFY

Tests first, then the artifact itself — and real hardware where only hardware tells the truth.

04 · RELEASE

Signed, gated, reproducible. Anything not verified yet is written down as not verified.

One Frame

A private, local-first photo journal for Android. One photograph and one sentence a day, encrypted on the phone. No account, no server, nothing leaves the device unless you export a backup yourself.

Problem

Journaling backlogs turn into homework, and “private” usually still means somebody else’s server.

Built

Domain and storage layers, UI, archive, encryption, bilingual copy, CI gates and Android release signing.

Technology

Flutter, Dart, SQLite, SQLCipher, AES-256-GCM, Android Keystore, local notifications.

Evidence

138 tests, clean static analysis, a signed APK, and encrypted storage confirmed by reading bytes off the phone.

Verified in CI · Built · Not deployed
